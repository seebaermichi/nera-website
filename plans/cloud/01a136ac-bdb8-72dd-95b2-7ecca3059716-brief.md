`pages/tutorials/canonical-links-seo.md` is stamped `plugin-canonical-links: 2.1.0`; the current release is **2.2.3**. What it says that no longer holds, and what it leaves out:

**The plugin, 2.2.3** (from its README and CHANGELOG; the package tarball
carries both — read them yourself: `npm pack @nera-static/plugin-canonical-links@2.2.3`
in a temp dir, or `node_modules/@nera-static/plugin-canonical-links/` in the
throwaway site):

- **Origin.** `origin` in `config/app.yaml` (read as `app.origin`) wins;
  `app_origin` in `config/canonical-links.yaml` is the fallback. A trailing
  slash is stripped. With neither, the plugin prints a warning once and writes
  no `meta.canonicalLink`/`meta.alternateLinks` at all (since 2.1.0 — before
  that it emitted `href="undefined/…"`).
- **The config file is optional.** With `origin` in `app.yaml` you get
  canonical links without it; you need `config/canonical-links.yaml` only for
  `available_languages` or a non-default `page_identifier` (default `slug`). The
  config file shipped inside the package is documentation only — Nera reads the
  site's own file and never merges the two.
- **`base_path`** (2.2.3, a fix): URLs are `origin + app.basePath + meta.href`.
  A site with `base_path: /docs/` in `config/app.yaml` gets
  `https://example.com/docs/page.html`. Without `base_path` the output is
  byte-identical to before.
- **Alternates.** `available_languages` lists the language codes; omitting it
  disables alternate links silently (`meta.alternateLinks` is then an **empty
  array**). Each page must set **`lang`** — without it the page gets a canonical
  link but no alternates, silently. Translations must share an **identical
  `page_identifier` value** (`slug` by default); pages without the key are
  never matched (since 2.2.1 — before, all identifier-less pages were
  cross-linked to each other).
- **Data:** `meta.canonicalLink` = `{ href, rel: 'canonical' }`,
  `meta.alternateLinks` = `[{ href, hreflang, rel: 'alternate' }]`. Both absent
  when no origin resolves; the shipped partials guard for that.
- **Plugin order.** Plugins run `start:` → alphabetical → `end:` from
  `config/plugin-order.yaml` (Nera core ≥ 4.2.0). `plugin-canonical-links` sorts
  before `plugin-tags`, which **generates** its tag-overview pages while it
  runs, so those pages get no canonical link unless canonical-links is listed
  under `end:`. Generated pages have no frontmatter identifier → canonical link,
  no alternates. This site's `config/plugin-order.yaml` does exactly that
  (`end: plugin-canonical-links, plugin-search`).
- **Templates.** `npx nera-canonical-links` publishes `index.pug` + `partials/`
  to `theme/views/vendor/plugin-canonical-links/` (skips if the folder exists;
  `--force` overwrites). The templates emit `link` elements only, no classes.
- **Include.** README form: `include /vendor/plugin-canonical-links/index`
  (root-absolute, resolves against `theme/views/`, needs core ≥ 4.3.0 — every
  site on `@nera-static/nera` has that). The relative
  `include ../vendor/plugin-canonical-links/index` is equivalent only from a
  layout in `theme/views/layouts/`, and is what you need on core 4.1–4.2. A bare
  `include vendor/…` (no slash, no `../`) fails the build from a layout.
  **This site's own `layout.pug` uses the relative form** — so the current
  closing line "Every page on this site carries one, built exactly this way"
  must not claim the site uses the root-absolute include. Reword it truthfully
  (e.g. the site uses the relative form, which is equivalent from its layout).
- **This site specifically:** `config/canonical-links.yaml` sets
  `app_origin: https://nera.js.org` (no `origin` in `app.yaml`) and
  `available_languages: [en, de]` — `es` is left out on purpose, pending a
  native-speaker review. Do not present the site as emitting `es` alternates.
- **`@nera-static/plugin-sitemap`** (1.0.1) reads the same origin — `origin`
  in `app.yaml`, else `app_origin` from `config/canonical-links.yaml` — and
  builds `origin + base_path + page path`, so its URLs and the canonical URLs
  agree (on a `base_path` site only with canonical-links ≥ 2.2.3).

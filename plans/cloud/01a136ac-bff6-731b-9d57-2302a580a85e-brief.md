**Nera rules that matter here.** A page renders only if its frontmatter has
`layout`. Plugins are found automatically from the site's `package.json`
(`@nera-static/plugin-*`); a plugin reads its config from the **site's**
`config/<name>.yaml` (the copy inside the package is documentation only, never
merged). Since core 4.7.0, `meta.createdAt` comes from the frontmatter's
`createdAt` (or `date`) before falling back to the file's birth time — which on
a CI checkout is the same for every file, hence "give each post a `createdAt`".

**`@nera-static/plugin-simple-page-list` 2.3.3** (from its README; the tarball
carries README, `config/simple-page-list.yaml` and `views/simple-page-list.pug`
— read them in your throwaway site):

- Config in the site's `config/simple-page-list.yaml`. Without one (or with
  neither `page_path` nor `page_paths`) the plugin is a no-op and
  `app.pageList` is not set.
- `page_path: /posts` (legacy, still supported) → flat array `app.pageList`.
  `page_paths: [/posts]` → grouped object `app.pageList.posts` (key = last
  segment, or an explicit `key:`). Paths match a page's directory, anchored at
  a segment: `/posts` includes `/posts/x.html` and `/posts/2024/x.html`, not
  `/posts.html`.
- `sortBy` (`date`, `title`, any frontmatter field; default `date`),
  `sortOrder` (`ascending`/`descending`), `more_link_text`, `exclude_pages`
  (rendered paths such as `/posts/index.html`). "If `date` is missing, Nera's
  `createdAt` is used as a fallback" — **prove** that a post with only
  `createdAt` sorts correctly (see scenario below); if it does not, say so and
  use what does work.
- Each list item is the page's `meta` plus `date` (ms) and `moreLinkText`; use
  `href`, `title`, `description`.
- `npx nera-simple-page-list` publishes `simple-page-list.pug` to
  `theme/views/vendor/plugin-simple-page-list/` (on a `nera new` site), and
  **skips if that folder already exists**; `--force` overwrites (and discards
  edits). Include it with `include /vendor/plugin-simple-page-list/simple-page-list`
  (root-absolute, core ≥ 4.3.0) or relatively
  `include ../vendor/plugin-simple-page-list/simple-page-list` from
  `theme/views/pages/`.
- The shipped template handles both shapes: flat → one
  `section.page-list` with `h2.page-list__title Recent Pages` and the
  articles; grouped → one `div.page-list__group` per key, each with an
  `h3.page-list__group-title` showing the **raw key** (e.g. `posts`). The
  heading text "Recent Pages" is hard-coded in the template (no config key) —
  the reader edits their vendored copy if they want other text; that is the
  point of publishing it. BEM classes: `page-list`, `__title`, `__group`,
  `__group-title`, `__item`, `__header`, `__item-title`, `__link`,
  `__description`, `__footer`, `__more-link`.

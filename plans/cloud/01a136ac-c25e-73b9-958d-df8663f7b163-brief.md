**The plugin, `@nera-static/plugin-navigation` 3.1.0** (from its README and
CHANGELOG; the package tarball carries both — read them yourself in the
throwaway site under `node_modules/@nera-static/plugin-navigation/`):

- **Class keys** (README "Class names", CHANGELOG 3.0.0). All three are
  optional; the defaults are `nav_class: nav`, `active_class:
  nav__link--active`, `active_path_class: nav__link--active-path` — the values
  the tutorial's example sets, so that example changes nothing versus omitting
  them. `nav_class` is the **BEM block name** and the family derives from it:
  `.nav`, `.nav--list`, `.nav__item`, `.nav__link`. `nav_class: mainmenu`
  renames the whole family to `.mainmenu`, `.mainmenu--list`,
  `.mainmenu__item`, `.mainmenu__link`, `.mainmenu__link--active`
  (and `--active-path`). `active_class` and `active_path_class` override just
  those two, independently of `nav_class`. `active_class` goes on the link to
  the current page; `active_path_class` on a link whose directory contains the
  current page (the site root is never marked as an ancestor).
- **Which template emits what** (README "Styling"): the block, `--list` and
  `__item` classes come from the link-list template (`linkListNav`, a `<ul>`)
  only; `simple-navigation` / `pipe-separated-navigation` emit `<nav>` with the
  link classes only. The tutorial uses `linkListNav`, so the full family applies.
- **Before 3.0.0** these keys were ignored (class names were hardcoded in the
  templates). **Upgrading from 2.x:** publishing (`npx nera-navigation`) skips an
  existing `theme/views/vendor/plugin-navigation/`, so a site that published
  under 2.x keeps the old templates and `nav_class` appears to do nothing. Fix:
  `npx nera-navigation --force`, which overwrites the vendor folder and
  **discards any edits** made to it — so: run it if the copy was never edited,
  otherwise diff first / carry the edits over. The same `--force` picks up the
  3.1.0 `aria-label` change; mention it only if it fits naturally.
- **`href` is required.** An entry without a string `href` is skipped with a
  console warning naming its position; the build still succeeds. `path` is
  derived from `href` (not user-supplied); extra keys pass through.

**Versions** (`npm view`, 2026-10-13): `plugin-navigation` 3.1.0, `nera` 1.11.0,

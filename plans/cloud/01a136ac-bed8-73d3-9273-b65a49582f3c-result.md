## Decisions

- The getAssets code is shown as an addition block (imports + `getAssets`, with a comment line standing in for getAppData), not as a full repeated file. The test assembles the full file from the blocks by script, so "exactly as the tutorial shows it" still holds.
- I did not add a `getMetaData` to the example plugin. The contract snippet lists it; the worked example needs only getAppData + getAssets.
- The example output JSON is the real throwaway-site output, page names included ("First/Second tutorial").
- Code-block comments stay in English in de/es, as the existing contract snippet already did. This keeps the blocks byte-identical.
- The docs link has no heading fragment. Built headings carry no `id`, so `#the-hook-contract` would not resolve. The text names the section ("The hook contract" / „Der Hook-Vertrag“ / «El contrato de hooks») instead.
- The warning strings are quoted from core 4.16.0 source and confirmed by the throwaway build. They stay in English in de/es, because that is what the console prints.
- Section headings: the new section is "Hand over a file with `getAssets`" / „Übergib eine Datei mit `getAssets`“ / "Entrega un archivo con `getAssets`". The imperative matches the existing "Build it" / "Use it in a layout".
- I kept the simplified `href.startsWith('/tutorials/')` filter. It works in the throwaway site and is still called simplified.
- Commit attribution: I followed the brief's `Co-Authored-By: Claude <noreply@anthropic.com>`.

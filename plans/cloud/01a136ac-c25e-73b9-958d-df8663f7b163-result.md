## Decisions

- Order inside section 2: class-key paragraph → `href` line → `>` upgrade note, then the
  existing "Need more than one menu?". The `href` rule sits next to the config it is about;
  the upgrade note as a `>` note mirrors the one in section 3 and only concerns some readers.
- Listed `.mainmenu__link--active-path` in addition to the issue's five names (brief:
  "and `--active-path`"); it is in the scenario-2 output.
- Added one clause the brief did not ask for: when renaming, drop the two state keys,
  because the example sets them explicitly and scenario 2b shows they then stay
  `nav__link--active`. Without it a reader copying the example and changing `nav_class`
  gets mixed names.
- Described `active_path_class` as "a link whose directory contains the current page (the
  site root never counts)" — the plugin's real rule, rather than "ancestor link", since
  scenario 2 also marks `/about/me.html` as active-path when on `/about/index.html`.
- The 3.1.0 `aria-label` change is not mentioned: it does not affect `linkListNav`, which
  the tutorial uses.
- The note words the `--force` caveat as "if you edited your copy, save your changes first
  and carry them over" rather than "only run it if never edited" — same advice, actionable
  for both cases.
- Commit trailer: `Co-Authored-By: Claude <noreply@anthropic.com>` as the brief asks.

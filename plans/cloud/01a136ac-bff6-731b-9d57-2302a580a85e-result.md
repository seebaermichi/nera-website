## Decisions

- **Flat `page_path: /posts`**, not grouped `page_paths`: the grouped template
  prints the raw key `posts` as an `h3` under "Recent Pages", at the same level
  as the post titles — wrong text and a flat heading hierarchy for a one-section
  blog. Flat gives `h1` (page) → `h2` "Recent Pages" → `h3` per post. The
  tutorial mentions why in one sentence and leaves grouped lists to the plugin
  README (not linked, since the catalog links it).
- **The published `simple-page-list.pug` is shown in full** (45 lines), under
  "This is the template you published": the issue asks for "the template code
  shown in full", and the reader is told to edit it (heading "Recent Pages" is
  hard-coded). The block is byte-identical to the 2.3.3 file; a later plugin
  release that changes the template makes this block drift — the stamp records
  2.3.3.
- **Config shows all four keys** (`page_path`, `more_link_text`, `sortBy`,
  `sortOrder`) although the last three equal the defaults, so the reader sees
  where to change sorting.
- **Include path** is the root-absolute `/vendor/…` form (core ≥ 4.3.0; nera
  1.11.0 ships core 4.16.0), with one sentence on what the slash means. The
  relative form is not shown, to keep one way.
- **`blog.pug`** uses `!= content` on its own line inside `main` (the scaffold's
  `main !{ content }` cannot take a child include). No `nera:scaffold-default`
  marker, since it is the reader's own file.
- **Post files stay English in de/es** (titles, text, `index.md`): the blocks
  must match the files the tutorial was verified with, and the rendered list
  text ("Recent Pages", "Read more") is English anyway. The prose quotes the
  English titles ("My second post" above "Hello world"). Before, de/es used
  translated post titles ("Hallo Welt", "Hola mundo").
- **Third test post** is only in the verification, not in the tutorial (the
  brief asks for at least two posts; two show newest-first).
- **Sitemap pointer** goes through the canonical-links tutorial (for the origin)
  plus the plugin catalog, because there is no sitemap tutorial; images and code
  blocks link the catalog `/plugins/index.html` (the link form the site already
  uses, with `/de/`/`/es/` twins).
- **Search index:** `theme/assets/search-index*.json` are tracked and the build
  rewrites them; the regenerated entries are committed so the repo matches the
  build (the previous tutorial issues committed them the same way).
- **`pages/tutorials/index.md` (+ de/es)** needs no change: its text ("from a
  first blog to wiring up individual plugins") stays true, and the list shows
  the new `description`.

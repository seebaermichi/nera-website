## Decisions

- New section `## Checks and deploy` placed right after "Build" (Build kept
  as is); the closing "That's the entire stack" paragraph moved below it.
  Section count 6 → 7 in all three languages (the plan said 7 → 8; I had
  miscounted).
- `--check` described as "reports what it finds; findings are warnings, so they
  fail the run only for a rule `config/validate.yaml` promotes to an error" —
  not "keeps the output free of warnings" (the issue's wording), because the
  site has 3 warnings today and no `config/validate.yaml`.
- `test.yml` trigger described as "every push to `main` and every pull request
  against it" (the workflow also lists `master`, which this repo does not use).
- The `skill-zip` row links "The Nera skill" to `/docs/using-ai.html`
  (`/de/…`, `/es/…`); the local-plugin sentence also says `skill-zip` reads the
  skill from the installed `@nera-static/nera` (from its header comment).
- Link text to the local-plugin tutorial uses that page's title in each
  language ("Write your own local plugin", "Schreibe dein eigenes lokales
  Plugin", "Escribe tu propio plugin local").
- `description` changed in all three languages: "the local plugin behind it"
  was wrong (three local plugins) → "the local plugins, and how it is checked
  and deployed".
- Stamp at npm latest (as the brief asks), although the site builds with the
  older lockfile versions; no page claim depends on the difference.

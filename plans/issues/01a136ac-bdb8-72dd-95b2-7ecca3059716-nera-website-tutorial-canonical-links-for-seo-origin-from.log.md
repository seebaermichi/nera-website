## Today
`pages/tutorials/canonical-links-seo.md` is stamped `plugin-canonical-links: 2.1.0`; the current release is **2.2.3**. What it says that no longer holds, and what it leaves out:
- "`app_origin` is the only value you must set". The README now documents `origin` in `config/app.yaml` as the source and `app_origin` as a fallback, and **the config file is optional** when `origin` is set. Without any origin the plugin warns once and emits nothing (2.1.0).
- **`base_path`** (2.2.3): canonical and alternate URLs are `origin + app.basePath + meta.href`, so a site served from a subdirectory gets its real URL. Not mentioned.
- The page `description` promises "alternate-language link tags", but the body never shows them: `available_languages`, a `lang` in each page's frontmatter (without it a page gets no alternates), translations sharing an identical `slug` (the `page_identifier`), and `meta.alternateLinks` (an empty array when no languages are configured).
- **Plugin order**: pages generated by other plugins (the tag pages from `plugin-tags`) only get a canonical link if `plugin-canonical-links` is under `end:` in `config/plugin-order.yaml`, because alphabetically it runs before `tags`. This site does exactly that.
- The include is `include ../vendor/plugin-canonical-links/index` (relative). The README documents the root-absolute `include /vendor/plugin-canonical-links/index`; use the README's form and explain when the relative one applies.

## Instead
The tutorial teaches the 2.2.3 behaviour: origin from `app.yaml`, optional config, `base_path`, a worked hreflang example on two languages, the `end:` ordering, and the README's include. Mention that `@nera-static/plugin-sitemap` reads the same origin and `base_path` (link the sitemap tutorial once it exists).

## Why
SEO tags fail silently: a wrong canonical URL renders fine and is only noticed in a search console weeks later.
